# GPU、云端与复杂场景：工程测试协议

本文件定义本项目接下来的验收方法，是设计协议，不是认证标准或已执行报告。当前物理核心到05B、场景/实验合同到06；05B 本机 MinGW Debug/Release 各23/23，06场景合同已加入本机测试。GPU、云端、复杂碰撞与长跑尚未验证。

配套学习手册：`../../cloth_sim_lectures/testing_protocol.tex`，编译输出 `../../cloth_sim_lectures/output/pdf/gpu_cloud_testing_protocol.pdf`。机器可读的**计划清单**在 `../tests/plans/complex_scene_matrix.json`，不能被CTest直接运行，也不能算测试通过。

## 1. 必须拆开的四个问题

1. **实现正确吗？** 导数、装配、固定点、CPU/GPU输出与错误语义。
2. **离散解够准确吗？** 同模型的时间/空间/迭代误差，参考解可信度与条件性。
3. **模型符合目标物理吗？** 对独立实测的拉伸、弯曲、摩擦等做验证；与原Python一致只验证迁移。
4. **复杂负载下可靠、够快吗？** 接触完整性、失败率、内存、长跑和端到端时间。

云端是执行环境。复杂动画、GPU利用率、未崩溃、18个小测试全绿，都不能单独回答全部四个问题。

## 2. 当前能力与前置

`Mesh`存二维材料参考坐标、三维位置和三角形，只有规则矩形生成器；现有CLI固定2×1 cells、6节点。通用弯曲/能量约束可接收合法三角拓扑，但距离/剪切构建器依赖规则矩形。能量模式目前没有弯曲项。尚无C++接触/摩擦、复杂障碍、BVH、自碰撞、CCD、运动学障碍、CUDA后端。

- **复杂布料**需要合法二维裁片/参考度量、任意拓扑输入和质量校验。OBJ三维外观和贴图UV不能直接充当无畸变、有物理尺度的参考数据；当前每节点只有一个二维参考坐标，也未实现多裁片缝合。
- **复杂碰撞体**可以先是静态椅子/人形，再做有表面速度的运动学障碍；静态障碍不必先实现刚体动力学。
- **动态刚体或体积软体**需要各自的运动学、惯量或体积离散，三角膜表面不能替代体积压缩模型。

保持顺序：05B补原平面接触/摩擦；06补场景配置与输出；07已完成当前有效范围的原Python/C++交叉验收，下一步可接真实云端CPU CI。任意复杂资产输入作为后续扩展，再按碰撞能力解锁复杂障碍、自碰撞/CCD；CUDA阶段迁移已验证的热点并复验。

## 3. 六道验收关

| 关卡 | 输入与操作 | 必须保存/判定 |
|---|---|---|
| G0 可复现输入 | 源码归档/提交、未提交变更、资产、场景、单位和模型合同 | 内容SHA-256；构建选项、参考数据来源；没有身份信息的结果无发布资格 |
| G1 数学与CPU基线 | 解析小例、差分/不变量、Linux/Windows、ASan/UBSan | 断言、退出码、JUnit、完整失败日志；同一模型的参考轨迹 |
| G2 复杂场景数值质量 | 加密/收紧容差；完整几何、接触、力学与驱动功检查 | 每步极值、误差/残差、模型有效域、失败率；禁止只看保存帧 |
| G3 GPU正确与内存安全 | 真设备CPU/GPU对照、精度实验、Compute Sanitizer | 后端/设备确认、核与同步错误、越界/初始化/同步检查；不能以空跑或CPU回退通过 |
| G4 性能与资源 | 固定机器Release、预热、重复、相同质量/输出 | 原始样本、p50/p95、墙钟、阶段耗时、RAM/显存；不混入工具检查开销 |
| G5 云端长跑与回归 | 多种子、复杂接触、持续运行、限额、终止/恢复 | 所有失败、超时/中断、内存趋势、检查点与恢复误差、最终退出和产物 |

某测试可因能力未实现标`unsupported`或`not_run`；必须GPU的作业若无设备，则环境失败，不能变成绿色跳过。预期拒绝的坏输入需验证明确错误，不能算成功完成一条物理轨迹。

## 4. 复杂场景阶梯

| 编号 | 场景 | 自动检查与前置 |
|---|---|---|
| C01 | 参考布料平移、旋转、自由落体 | 能量/梯度变换、质量、固定漂移、解析轨迹、最小J；已有库层基础，批量场景运行器待补 |
| C02 | 16²→64²→128² cells悬挂布 | 分组R、独立s_x、固定误差、完成率、J、时间步细化、RAM/显存；06参数化后运行 |
| C03 | 带孔/缺口、非均匀三角裁片 | 参考坐标、绕序/面积、质量；仿射patch的局部解析量或小规模参考；需要任意拓扑输入 |
| C04 | 平面落布/水平滑动/斜面小例 | 厚度间隙、穿透、法向反力、摩擦锥、耗散/外功、固定点；05B后，斜面另需法向可配置 |
| C05 | 球/胶囊覆布 | 距离与接触特征对照、整个面片的漏碰/穿透、接触残差；增加解析形状查询和响应 |
| C06 | 静态椅子/凹三角网格 | 小规模BVH候选对照穷举无漏、完整窄相、穿透、失败、候选数；需要资产与碰撞模块 |
| C07 | 运动学人形/胶囊人 | 轨迹/表面速度、相对接触、驱动功、穿透；先定义运动学驱动，不能要求受驱动系统动量守恒 |
| C08 | 多层折布、高速穿越 | 自碰撞邻接过滤、VT/EE、层间距、CCD碰撞时间与穿隧事件；后续能力未实现 |

C05必须包含“顶点全在球外，但面片/边穿过球”的最小回归例。仅采样顶点距离不能证明整片布没有穿透。C06的BVH只负责候选，不替代窄相；C08只在保存帧检查也可能漏掉中途穿隧。

分辨率与接触难度分开变化；网格数、自由度、约束数、候选/接触数、迭代次数共同定义负载。初始规模先测内存，隐式SparseLU可能因填充而先受RAM限制，不能把XPBD可跑的节点数直接当隐式路径的可行预算。当前`E/s`能量模型固定每单元参数会随网格变化，距离网络也需确认材料缩放；加密图不自动成为连续模型收敛证据。

## 5. 误差与通过门槛

短时CPU/GPU位置比较可用`max_i ||x_gpu-x_ref|| / L`和质量加权范数，速度另用V归一化；一般判定写成`error <= atol + rtol * reference_scale`，明确范数、单位、尺度。接触另报告`max(0,-gap)`、相对厚度穿透、漏碰事件、摩擦锥/功、求解残差；小R不保证完整驻点或真实轨迹准确。

阈值来自应用允许误差、小例/参考加密研究及数值精度；在测GPU性能前冻结。当前计划文件的门槛标为`pending_calibration`，`release_ready=false`，不能自动发布。不能先看到误差后放宽阈值，也不能强制所有场景共用1e-6。

长时非线性运动不必逐节点逐位一致：先验证短时轨迹，再验证明确物理观测、失败率、接触事件与必要统计。守恒只在相应封闭系统和外载假设下检查；固定边、地面、重力、阻尼及运动学驱动必须列入交换/功账。实测对照与离散一致性分开归档。

## 6. GPU测试必须额外覆盖

相同模型、质量、参考网格、材料/弯曲、接触、步长、精度与停止政策，才有可解释的后端比较。GS改Jacobi/着色会改变迭代，先重新验证质量，再测速度；GPU按更少迭代运行不能直接称等价加速。

NVIDIA Compute Sanitizer提供memcheck、initcheck、synccheck、racecheck；为错误设置非零退出。racecheck主要检查共享内存访问危险，不能证明全局节点累加无竞争；还要检查写入所有权、原子/归约/着色和重复对照。[官方说明](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html)

总墙钟作为主指标，同时保存CUDA事件时间、传输/求解/碰撞/同步/I/O阶段时间；阶段有重叠时不能简单相加。Nsight Systems用于定位CPU/GPU空隙与传输、同步；NVTX标注阶段。分析工具运行与正式性能样本分开。[官方说明](https://docs.nvidia.com/nsight-systems/UserGuide/index.html)

加速上限受CPU剩余部分限制。若只有30%时间可加速，即使它快10倍，理想端到端也仅约`1/(0.7+0.3/10)=1.37`倍。需要测量完整路径；CPU保持原求解而仅GPU算局部单元，只能声称该混合路径的实际加速。

## 7. 云端执行一轮的具体流程

1. 冻结源码、资产、场景、阈值和运行种子；当前源码未提交时，连同未跟踪文件制作源码快照并计算散列，不能只记一个空仓库提交号。
2. 准备一台NVIDIA单卡机器，确认驱动/工具链/容器兼容并记录GPU型号、显存、架构、驱动、编译器、运行时和容器digest。尚未测量前不承诺某机型速度。
3. 先验证设备可见，再运行真实CUDA小测试；`nvidia-smi`或容器启动成功只说明环境可见，尚未验证物理计算。NVIDIA的[容器样例](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/sample-workload.html)用于环境检查。
4. 从冻结输入构建CPU/GPU测试程序。当前项目还没有CUDA构建target或GPU执行选项，不能把未来命令当现成接口。
5. 跑G1/G3小例与内存检查，通过后跑C01—C08中已实现的数值场景；先小规模，再增加分辨率和接触密度。
6. 使用独立Release性能作业预热并重复测量；保存原始样本与质量指标，不删除慢样本、失败、OOM或超时。
7. 执行有上限的长跑和恢复试验。检查点在完整物理步提交后保存；记录位置/速度、模型、时间、随机状态，未来还需接触缓存/热启动等隐藏状态。
8. 无论成功失败都上传`report.json`、JUnit、环境/构建日志、源与资产散列、逐步极值、失败前状态、计时与必要trace。
9. 比较固定硬件历史基线，数值与资源门槛通过才讨论性能回归和发布。云中断与物理失败分开统计，未完成不能登记成功。

可以用云VM上的自管runner或云批处理；[GitHub self-hosted runner](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners)可选择硬件，但维护责任也在自己。当前没有部署或定时任务。CPU的真实云端CI可先于CUDA接入。

## 8. 本轮实际做了什么

审查代码/现有CI并核对官方工具文档，新增协议、场景计划和TeX手册；06增加场景/实验合同与可重放CLI。尚未远端运行。当前Shell的PATH中未找到`nvidia-smi`、`nvcc`，找到了`docker`命令；这不证明硬件不存在，也不证明Docker服务或GPU容器可用。没有运行复杂模拟、GPU核或云作业。
