# 布料数值与 GPU 子路线：每次推进一个可验收的阶段

项目采用 C++ / CMake 与后续 CUDA，**先完成原项目重写与验收，再扩展**。任务 01--07B 已实现当前有效范围，05包含05A单元能量XPBD与05B原平面接触/摩擦，06提供场景/实验合同，07完成迁移验收，07B接入合法任意三角拓扑的距离路径；下一阶段是云端CPU CI、复杂场景和CUDA。编号以[迁移优先总路线](05_multiphysics_architecture.md)为准；下面1–8是知识子路线阶段，不等同于全项目任务编号。

起点：会基础 C++，CMake 从头学；目标后端为 NVIDIA CUDA。阶段按验收推进，不预设必须几天完成。每次一起做“解释一个概念 → 你改一小处 → 构建和测试 → 看证据 → 总结原因”。不要求你一开始读完所有实现。

## 1. 学会构建，并保住数学基础（任务 01 已完成）

学习：头文件/实现文件、静态库与可执行程序、CMake target、构建目录、Debug/Release、CTest。

产物：网格、集总质量、单元能量/梯度、11 个 Python 对照样例。为减少初学时的依赖干扰，这一课只用标准库和固定大小数组；不是要在后续自己实现一套通用线性代数库。

验收：你能独立执行 configure/build/test，能解释 `target_link_libraries` 和 `PUBLIC`，能通过测试说明质量与厚度的关系。初学时先跟做 [第一课](03_lesson_01.md)，再按任务顺序推进。

## 2. 从单元走向稀疏系统（任务 02 已完成）

学习：解析 Hessian、自由度编号、固定边界、COO/CSR、预计算参考数据、稀疏矩阵库的选择与锁定版本。

产物：单元 9×9 Hessian、能量/梯度/Hessian 装配、集中/一致质量；几何拓扑与可变状态分开。单元接口保持纯函数，便于 CPU/GPU 共用验收规则。

验收：Hessian 对称且与梯度差分一致；普通与 J 延拓区均检查；小网格装配与原 Python 对齐；固定自由度映射可验证。单元与系统都覆盖，防止局部正确、装配错误。

任务 02 提供最小 CSR 与两种质量、全局装配和固定映射，历史验收为 Debug/Release 各 7/7 CTest。任务 03 已增加离线哈希锁定的 Eigen 5.0.0 稀疏 LU 适配；自有 CSR 仍只承担装配、约化与乘法。

## 3. 第一条完整模拟路线：串行隐式 Euler（任务 03 已完成）

学习：增量势能、Newton、线搜索、非凸性、残差与收敛阈值、失败时间步的处理。

产物：无接触的无窗口时间推进；状态分别记录 `finite_state / solver_converged / committed / failure_reason`，未收敛步返回原状态。固定教学场景 CLI 可保存参数和结果；完整原场景配置仍在任务 06。步长回退作为后续独立变化验证。

验收：静止、自由落体、固定边界、弹性变形与 Python 轨迹对照；使用相同质量模式、步长、容差和初态。Hessian 不一定正定，不能直接把直接解法换成 CG 并假定可用。

任务 03 历史验收为 Debug/Release 各 11/11 CTest，含 6 条 Python 轨迹的 48 步、最终残差复核、线搜索与失败回滚、CLI 成功/失败退出。Eigen 包离线核验和解包，不依赖下载。详见 [第三课](07_lesson_03.md)；Linux/MSVC/sanitizer/Docker/GPU 尚未实跑。

## 4. 接触、摩擦与第二类求解器

学习：地面罚势能、法向冲量、Coulomb 摩擦、离散能量记账；Gauss-Seidel 顺序约束更新与 XPBD 柔度。

产物：任务 04 的距离/剪切/弯曲 XPBD、05A 的单元能量约束与 05B 的原平面接触/摩擦均已实现。05B 在隐式 Newton 内加入罚势，XPBD 在投影后处理地面并重测残差；固定点、冲量和耗散分别诊断。运行与验收见 [05B 指南](11_lesson_05b.md) 及 `../cloth_sim_lectures/task05b.tex`。

验收：固定节点不被接触改动；穿透在已记录的容差内；摩擦锥、耗散和停止行为通过。XPBD 分开报告有限状态与约束残差。距离 XPBD、`C=E/scale` 的能量 XPBD、隐式膜不是自动等价的材料模型；不靠三者动画相似来证明一致性。

任务 04 将 XPBD 有限状态、按组柔顺残差和提交分开：预算模式可提交近似，严格模式残差不达标时回滚。Python 轨迹相符不代表全部 32 步都收敛；退化约束在 C++ 中明确无效并拒步，而不是把原零角/零梯度当满足约束。

05A 额外学习 `std::variant` 第三种类型如何接入通用投影、能量尺度与柔度的联合缩放，以及 NH 诊断能量和实际平方约束势的区别。CLI 使用 `--model energy`，独立报告无量纲柔顺残差；四组诊断、乘子与两类能量分别保存。配套数值分析手册补充小变形四次势、残差/驻点边界和可复现实验。

历史任务04为各15/15、05A为各18/18；当前05B本机Debug/Release完整CTest各23/23，通过32个实际触地原路径步。06合同加入后完整各28/28，07B后各29/29，另行运行原Python validation 71项、自定义网格场景和14项来源散列。下一阶段为真实云端CPU CI、复杂场景和CUDA，不把当前小例当作复杂设备验收。

## 5. 先建立可信的性能基准

学习：性能剖析、预热、p50/p95、计时边界、工作负载、公平比较、机器元数据。

产物：配置化规则矩形场景、批量无窗口 CLI、实验状态文本、失败退出码、提交前缀与分阶段计时。分开记录单元核、装配、线性求解、接触与后处理，也记录包含全部步骤的墙钟总耗时；JSON/CSV与完整原场景输入仍在07验收阶段整理。

验收：同一物理模型、同一误差/收敛要求才比较速度；失败样本也统计。先用小/中/大规模曲线寻找瓶颈，再选优化对象，不预先承诺加速倍数。

## 6. CPU 多核并行

学习：OpenMP、共享写冲突、线程局部缓冲、归约、线程数与内存占用、Amdahl 定律。

产物：先并行独立的单元计算，再处理共享顶点/稀疏值的装配。基准固定线程数，避免和底层线性代数库嵌套超额开线程。

验收：1/2/4/...线程的数值误差、失败率和物理指标达标；记录加速、内存与规模。当前 XPBD 原地写回共享顶点，不能直接加 `parallel for`。着色和 Jacobi 需要作为不同执行策略重新验证。

## 7. CUDA 入门：一个真实的 GPU 单元计算路径

学习：host/device、线程/块、设备内存、连续访问、SoA、同步、CUDA events、异步错误检查。

产物：批量单元能量/梯度的 CUDA 实现，先用 FP64 与 CPU 基准对齐。避免过早把公开接口锁死为 GPU 布局；从当前清楚的小结构转换到设备批量数据。

验收：真实 NVIDIA GPU 上的结果与 CPU 对照；Compute Sanitizer；小/中/大规模测试。同时报告纯核时间和含传输/同步的总时间。小网格可能没有收益，这也是有效结论。

## 8. GPU 完整路径与云端持续验证

学习：设备端驻留、全局归约、预条件、matrix-free 的取舍、图着色、GPU 性能剖析。

产物：根据第 5/7 阶段的测量决定下一步：GPU 隐式求解路径，或独立的着色 XPBD 路径。若先做 XPBD，明确它与隐式路径的模型/精度差异。避免每次 Newton 都在 CPU/GPU 间搬整个矩阵。

验收：真设备端到端数值/收敛/稳定性通过；云端保存硬件、驱动、CUDA、编译器、提交版本与完整失败材料。稳定硬件上再设性能回归阈值。详见 [云端验证](04_cloud_validation.md)。

## 与扩展总路线衔接

本文件的单元 Hessian、隐式推进、XPBD、原接触摩擦和实验验证将在总路线任务 02--07 完成。刚体、通用碰撞、流体和双向耦合只在迁移验收之后展开。各向异性材料、参数辨识、Python 绑定、多 GPU/MPI 等仍是可选专题；云端首先是部署和测试环境，不自动意味着需要分布式求解。

完成后适合展示的证据：公式与代码的对应、失败处理设计、测试矩阵、可复现命令、性能随规模变化的曲线、一次真实 GPU 剖析与优化的前后对比、已知局限。这些也能呼应截图里物理引擎岗位对数学、代码质量和技术文档的要求。
